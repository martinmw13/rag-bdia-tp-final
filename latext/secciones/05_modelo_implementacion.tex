archivos Mermaid \path{docs/diagramas/logico.mmd} y

comportamiento efectivamente implementado.

Las tablas usan claves internas \texttt{BIGINT GENERATED BY DEFAULT AS
IDENTITY}; los códigos de producto, cliente, proveedor, pedido y documento son
claves de negocio únicas. Las asociaciones puras usan claves primarias
compuestas y las claves foráneas históricas aplican \texttt{ON DELETE
RESTRICT}. Los estados cerrados se controlan mediante \texttt{CHECK}, sin
crear catálogos que no aportan comportamiento.

La integridad temporal se expresa con intervalos semiabiertos y restricciones
\texttt{EXCLUDE USING gist}. Esto impide que dos condiciones comerciales del
mismo cliente y producto se superpongan y evita dos versiones publicadas
simultáneamente para un documento. Los constraint triggers diferidos validan
al cierre de la transacción que todo pedido conserve al menos una línea y que
la evidencia coincida con el tipo de respuesta.

El recorrido documental es
\texttt{documento} $\rightarrow$ \texttt{version\_documental}
$\rightarrow$ \texttt{fragmento} $\rightarrow$ \texttt{embedding}. La
evidencia referencia el embedding exacto y permite reconstruir por relaciones
la versión, el documento, el archivo y el modelo utilizados. Los índices
B-tree acompañan joins y filtros observados; el índice HNSW cubre el acceso
top-k por distancia coseno.
