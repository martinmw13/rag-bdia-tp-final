\section{Relevamiento de datos necesarios}

Los datos se separan según su función. Un pedido se consulta con filtros y
relaciones exactas; un procedimiento escrito se recupera por similitud
semántica. Cada grupo también tiene un ciclo de vida distinto.

Las preguntas con una respuesta exacta no se resuelven por similitud. La
condición comercial vigente se obtiene por cliente, producto y fecha. Los
pedidos demorados se obtienen al relacionar pedidos, entregas e incidencias. La
estructura permite aplicar restricciones, agregar resultados y evitar
ambigüedades.

El corpus requiere más que el texto. Cada documento tiene una clase,
sensibilidad, procedencia y una o varias versiones. La versión conserva la ruta
relativa, el nombre, el tipo MIME, el tamaño y el checksum SHA-256 del archivo.
Así se verifica su identidad sin guardar el contenido completo en la base.

Cada versión se divide en fragmentos. El fragmento es la unidad vectorizada y
la que se muestra como evidencia. Así se identifica la sección y la versión que
sostuvieron una respuesta, en lugar de señalar el documento completo.

Cada perfil puede ver distintas clases documentales. El permiso relaciona un
perfil con una clase; si la relación no existe, el acceso se deniega. La
interacción y la auditoría registran quién consultó, con qué perfil, qué obtuvo
y qué evidencia se usó, sin copiar contenido sensible.

Se usan datos sintéticos para no exponer información personal, comercial ni
documentos internos. La misma carga se puede repetir con iguales conteos,
archivos, vectores y resultados esperados.
